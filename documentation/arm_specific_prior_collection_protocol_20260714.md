## 1. Purpose

This experiment complements, but does not replace, the common-prior dose experiment.
The common-prior design holds the pre-treatment expectation fixed within a
meeting-regeneration-forecaster comparison and therefore measures the immediate response to the
current text. The arm-specific design instead lets the forecast generated under each
textual arm become that same arm's prior at the next meeting. It measures the persistent
synthetic path generated by repeated exposure to an assigned communication trajectory.

The two designs answer different questions:

1. **Common prior:** How does the current textual stance change a forecast when the
   information state entering the current meeting is held fixed?
2. **Arm-specific recursive prior:** How far apart do synthetic forecast paths move when
   each textual stance is repeatedly applied and carries forward its own forecast state?

The recursive result must not be described as the one-shot causal effect of a current
communication. It combines current-text responses with accumulated synthetic state
dynamics.

## 2. Frozen textual arms

No new minutes are generated for this experiment. The collector reuses the exact texts
already stored for the five-regeneration referee dose run:

| Stored role | Paper label | Ordered dose |
|---|---|---:|
| `dove_high` | High-intensity dove | -2 |
| `dove_low` | Low-intensity dove | -1 |
| `neutral` | Neutral rewrite | 0 |
| `hawk_low` | Low-intensity hawk | +1 |
| `hawk_high` | High-intensity hawk | +2 |
| `original` | Published original text | Reference only |

The source run contains 71 meetings, five repeated rewrite regenerations, and all six roles.
The original text is identical across regenerations by construction; the five generated
roles retain their regeneration-specific text. Every task stores `source_run_id`, `source_role`,
and `source_text_hash`. The audit recomputes the source hash against the stored corpus and
rejects any mismatch.

## 3. Recursive assignment rule

Let $m=1,\ldots,71$ index meetings in chronological order, $d=1,\ldots,5$
index the frozen text regeneration, $a$ index the six textual roles, and $f$ index the
anchored or unanchored forecaster. Each $(d,a,f)$ combination is a separate recursive
trajectory.

All trajectories start from the same initial expectation:

\[
P_{1daf}=3.80.
\]

The forecaster receives the current text $X_{mda}$, the inflation target, and the
trajectory-specific prior $P_{mdaf}$, and returns a forecast level:

\[
Y_{mdaf}=F_f(X_{mda},P_{mdaf},\text{target}_m).
\]

For every subsequent meeting, the same arm's previous forecast becomes its next prior:

\[
P_{mdaf}=Y_{m-1,d,a,f}, \qquad m>1.
\]

There is no borrowing of priors across arms, regenerations, or forecaster types. In particular,
the high-hawk path never receives a prior produced by the low-hawk, neutral, dove, or
original path. The original-text reference also follows its own recursive trajectory.

## 5. Forecaster prompt and provenance

The experiment uses the already frozen forecast-only prompt
`forecaster_common_prior_v1`; the wording is not changed between the common-prior and
arm-specific-prior designs. Only the rule that supplies `previous_inflation` differs.
The exact prompt template is stored in `code/collection/src/prompt_iv/agents/prompts.py` and reproduced in
the common-prior protocol. It instructs the agent to:

- act as a Brazilian professional inflation forecaster;
- accept the supplied pre-treatment forecast and target as given;
- use only those values and the supplied communication;
- ignore remembered historical information;
- avoid inferring a treatment label;
- return only `nova_expectativa_inflacao` in a strict JSON schema.

## 6. Database-only collection

Task registration and every result event are written directly to SQLite. The collector
does not create JSONL, CSV, or text result manifests. Relevant tables are:

- `runs`: run-level design and provenance;
- `agent_tasks`: immutable task, state-group, prompt, and source-text information;
- `agent_result_events`: append-only execution events;
- `agent_results_latest`: latest result state for each task;
- `tone_scores`: previously stored text-manipulation scores used by the R analysis.

Resume logic accepts only a valid contiguous prefix of each trajectory. If a trajectory
stops, restarting the same run continues from its first unresolved meeting without
changing completed earlier states.

## 8. Prespecified analysis

The primary display outcome is the calibrated composite forecast level. The anchored and
unanchored forecasters are also reported separately. Calibration weights are re-estimated
from the run-time GPT-5.5 panel `outputs/work/gpt55_calibration_data.dta`, using the same
standard R specification as the common-prior analysis. That panel is constructed from the
142 original-minute forecasts in `common_prior_original_v1_20260712` before either analysis
runs.

For each outcome, the arm table estimates:

\[
Y_{mda}=\alpha_{md}+\sum_{a\neq\mathrm{original}}\beta_a
\mathbf{1}\{A=a\}+\varepsilon_{mda},
\]

where the original recursive path is the omitted arm and $\alpha_{md}$ are
meeting-by-regeneration fixed effects. Standard errors use two-way clustering by Copom meeting
and recursive trajectory (regeneration by textual arm), allowing arbitrary
cross-arm dependence within a meeting and serial dependence within a path. Meeting-only
clustered standard errors are retained as a machine-readable sensitivity check. Thus,
each $\beta_a$ is a persistent forecast-level gap relative to the recursive original
path, not a current-meeting revision from a shared prior.

The gradient statistic excludes the original arm and estimates a linear slope over the
ordered doses $-2,-1,0,+1,+2$, with the same meeting-by-regeneration fixed effects and
two-way clustered inference. The graph reports coefficients in basis points, with
`1 bp = 0.01 percentage point` stated directly on the panel.

All econometric estimation is implemented in R using `DBI`, `RSQLite`, `data.table`,
`haven`, `fixest`, `ggplot2`, `patchwork`, `scales`, and `jsonlite`.
